# Auth Feature

회원가입 흐름(① 약관 동의 → ② 이메일 인증 → ③ 가입 정보 입력 → ④ 가입 완료)을 관리합니다. 로그인은 이후 이 폴더에 추가합니다.

## 데이터 기준

- 입력 항목·규칙·오류 코드는 백엔드 회원가입 연동 문서, API 명세, DB DDL(`userAccounts`, `userProfiles`, `marketingConsents`)을 따릅니다. Figma는 화면 배치 참고용입니다.
- 화면의 입력 검사는 사용자를 돕기 위한 것이고, 최종 검증은 Backend가 합니다. 이름·비밀번호 규칙은 백엔드 가입 API와 **같은 규칙**으로 검사합니다.
- 비밀번호, 인증번호, 가입 토큰은 주소(URL)·브라우저 저장소·콘솔에 남기지 않습니다. 단계와 입력값은 화면 안 상태로만 관리하며 새로고침하면 처음부터 시작합니다.

## 회원가입 규칙

| 항목        | 규칙                                                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 필수 약관   | 만 14세 이상, 서비스 이용약관, 개인정보 수집·이용 (문구는 `data/signup-terms.ts`, 버전 저장 없음)                                           |
| 이메일 인증 | 인증번호 6자리, 발송 후 5분 유효, 재발송은 1분 뒤. 인증 성공 시 가입 토큰 발급, 인증 성공 후 30분 동안 한 번만 사용                         |
| 비밀번호    | 8자 이상, 영문 대문자·영문 소문자·숫자·특수문자(`!@#$%^&*`) 중 3종류 이상 (최대 64자·UTF-8 72바이트)                                        |
| 이름        | 대한민국: 한글 음절만 / 그 외 국가: 한글 불가, 다른 언어 문자·결합 부호·안쪽 공백·`-` `'` `’` `.` 허용 / 공통: 숫자·이모지 불가, 최대 100자 |
| 닉네임      | 가입 때 받지 않음. 가입 후 백엔드가 랜덤으로 만들어 Kafka로 Member 프로필에 저장                                                            |
| 휴대폰      | 필수, 하이픈·공백은 입력할 때 자동 제거. 휴대폰 인증은 하지 않음(외국인 가입)                                                               |
| 마케팅 수신 | SMS·이메일 각각 선택, 기본 선택 없음. 고르지 않으면 요청에 넣지 않음                                                                        |
| 가입 응답   | `202 Accepted` + `userUuid`. 자동 로그인 없음 → 완료 화면에서 로그인 화면으로 안내                                                          |

규칙은 `utils/validate-signup.ts` 한 파일에 모여 있습니다. 화면의 비밀번호 체크 목록도 이 파일의 `passwordRules`를 읽어서 그립니다.

## 임시 동작 (API 연결 전)

`api/signup-api.ts`의 함수 이름·입력·결과는 API 명세와 같고, 안쪽만 임시 동작입니다. 실제 메일 발송이나 가입은 일어나지 않습니다. API 경로가 확정되면 이 파일의 함수 안쪽만 실제 요청으로 바꿉니다.

| 확인하고 싶은 화면 | 입력 값                                                    |
| ------------------ | ---------------------------------------------------------- |
| 이미 가입된 이메일 | `taken@nirvana.test`                                       |
| 틀린 인증번호      | `000000` (그 외 6자리 숫자는 통과)                         |
| 재발송 대기        | 인증번호 받은 뒤 1분 안에 다시 받기                        |
| 가입 토큰 만료     | 인증 성공 후 30분이 지나서 가입 → ② 이메일 인증으로 돌아감 |

## Component layers

- `components/organisms`
  - `SignupProgress`: 진행 단계 (① ② ③)
  - `SignupTermsStep`: ① 필수 약관 동의
  - `EmailVerificationStep`: ② 이메일 인증 (`hooks/useEmailVerification`)
  - `SignupInfoForm`: ③ 가입 정보 입력 (`hooks/useSignupForm`)
  - `SignupComplete`: ④ 가입 완료 (이름으로 인사 + 입력 정보 요약)
- `components/templates/SignupFlowTemplate`: 단계 전환, 이메일·가입 토큰 보관, 단계가 바뀔 때 스크롤·포커스 처리
- `app/(user)/signup`: 약관 데이터를 template에 넘기고 페이지를 조립

입력 칸·버튼·선택박스는 `src/shared/components/ui`(`FormField`, `Button`, `SelectField`)를, 국가 목록은 `src/shared/data/countries`를 사용합니다.
